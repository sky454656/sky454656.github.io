For this exercise, we will fuzz **VLC** media player. The goal is to find a crash/PoC for [**CVE-2019-14776**](https://nvd.nist.gov/vuln/detail/CVE-2019-14776) in VLC 3.0.7.1.

**CVE-2019-14776** is an Out-of-bounds Read vulnerability that can be triggered via a crafted WMV/ASF (Windows Media Video) file.

An Out-of-bounds Read is a vulnerability that occurs when the program reads data past the end, or before the beginning, of the intended buffer.

As a result, it allows remote attackers to cause a denial of service or possibly obtain potentially sensitive information from process memory.

`.asf file` : Microsoft가 만든 멀티미디어 컨테이너 포맷

비디오, 오디오, 메타데이터, 스트림 정보를 담는 껍데기 역할

`.wmv file` :  Windows Media Video<br>
보통 비디오 코덱/포맷을 의미하지만, 실제 `.wmv` 파일은 대개 ASF 컨테이너 구조를 사용

`DemuxInit() in demux/asf/asf.c`  에 취약점이 존재한다고 한다.

이번 실습은 dictionary, harness, seed를 전부 제공했기 때문에 이를 이용해서 fuzzing을 하고, triage 및 패치까지 진행해볼 것이다.

# Partial Instrumentation

AFL++는 보통 프로그램 전체에 계측 코드를 넣음.

VLC media player 같이 모듈이 많은 프로그램에서는 문제가 생길 수 있음.

ex) seed로 ASF/WMV 파일을 넣었는데, 퍼징 중 mutation으로 파일 헤더가 망가질 수 있음

실습하면서 triage하기 원하는 취약점이 있을 텐데, 다른 triage 쪽만 계속 커질 수 있음.

이를 해결하기 위해 `AFL_LLVM_ALLOWLIST` 사용

## AFL_LLVM_ALLOWLIST

특정 파일이나 함수에만 AFL++ instrumentation을 넣는 설정

원하는 함수나 파일을 지정하고 list를 만들어서 환경변수로 값을 넘겨주면 해당 코드에만 coverage 계측을 넣음

복잡한 프로그램에서 특정 부분만 fuzzing target일 때 필요한 부분만 instrument하면, 관심 없는 코드 경로로 인한 noise를 줄일 수 있다

실습은 fuzzing 하면서 해보자

# 하네스 코드 분석

기존의 main을 main2로 이름을 변경

```c
-int main(int argc, char *argv[])
+int main2(int argc, char *argv[])
 {
     const char *filename;
     struct vlc_run_args args;
@@ -49,3 +49,66 @@
 
     return -vlc_demux_process_path(&args, filename);
 }
```

afl용 새로운 main()을 만들기 위함.

afl이 넘겨준 입력 파일 확인

```c
+	if (argc != 2) {
+		fprintf(stderr, "Usage %s <input file> \n", argv[0]);
+		return -1;
+	}
```

`argv[1]`  이 input file이 됨

```c
+	struct vlc_run_args args;
+	libvlc_instance_t *vlc;
+
+	vlc_run_args_init(&args);
+	vlc = libvlc_create(&args);
```

VLC demuxer를 실행하기 위해 필요한 환경을 한 번 초기화

persistent 모드

```c
+#ifdef __AFL_COMPILER
+
+	while (__AFL_LOOP(1000)) {
+
+#endif
```

```c
+
+		int fd = open(argv[1], O_RDONLY); // fuzzing input 열기
+
+		if(fd < 0){
+			printf("Error opening file \n");
+			printf("Errno: %i\n", errno);
+			return -1;
+		}
+
+		struct stat st;
+		stat(argv[1], &st);
+		len = st.st_size; // 입력 크기 확인
+
+		buf = (unsigned char *)malloc(len); // 메모리 할당
+
+		read(fd, buf, len);
+
```

```c
+//		libvlc_demux_process_memory(vlc, &args, buf, len);
+
+		vlc_demux_process_memory(&args, buf, len);
+
+#ifdef __AFL_COMPILER
+
+	}
+
+#endif
+
+}
```

AFL이 생성한 input을 `vlc_demux_process_memory()`에 직접 전달하여, 실제 취약점이 존재하는 VLC demuxer 내부 코드까지 도달하도록 함.

패치를 보면 기존 코드는 `return -vlc_demux_process_path(&args, filename);`  이런 형태.

즉<br>
`filename → VLC → 파일 open → parse 구조`

CVE-2019-14776가 VLC의 ASF demuxer에서 발생하는 취약점을 알고 있기 때문에  하네스에서는 AFL input을 직접 vlc_demux_process_memory에 넣음.

실제 취약점을 찾을 때는 먼저 공격 표면을 선정하고, 해당 코드에 효율적으로 도달할 수 있는 entry point를 찾아 하네스를 작성한다.
